# ZooKeeper 三节点集群测试说明

## 脚本与依赖

- 脚本：`test/test-zookeeper.sh`
- 容器：`zoo1/2/3`
- 宿主机端口：2181、2182、2183

```bash
bash test/test-zookeeper.sh
```

## 测试范围

沿着“容器 → 客户端端口 → 选举角色 → znode 操作 → 数据同步 → 配置与命令 → 清理”的流程验证 ZooKeeper 三节点仲裁集群。

## 详细测试流程

### 1. 检查容器和端口

检查 `zoo1/2/3`，并分别连接宿主机 2181、2182、2183。连接失败会记录对应节点和端口。

### 2. 识别 Leader/Follower

对三个端口发送 `stat`，解析 `Mode`。正常三节点集群应只有一个 Leader，其余为 Follower；日志还会记录版本、客户端连接数等返回内容。

### 3. 执行基本 znode 操作

通过 Leader 的 `zkCli.sh` 按顺序执行普通节点创建、读取、更新、删除，并测试临时节点和顺序节点。每一步都匹配 ZooKeeper 返回文本。

### 4. 验证数据同步

在 Leader 创建 `/sync-test`，然后分别从三个节点读取。同一数据必须能够从所有节点获取，否则指出具体未同步的节点。

### 5. 检查节点配置

读取每个容器的 `myid` 和 server 列表，确认节点编号及三节点配置一致。

### 6. 检查四字命令和连接耗时

执行 `ruok`、`stat`、`mntr` 等只读管理命令，记录各节点响应；随后进行五次短连接并计算总耗时和平均耗时。该耗时只用于课堂观察，不作为性能 SLA。

### 7. 清理与幂等性

删除 `/test-node`、`/sync-test`、临时/顺序节点等测试数据，然后逐个查询确认节点不存在。

## 结果判定

| 环节 | 通过条件 |
|---|---|
| 容器/端口 | 三个节点均运行且可连接 |
| 选举 | 一个 Leader，至少两个 Follower |
| znode | 创建、读取、更新、删除成功 |
| 同步 | 三个节点读取到相同数据 |
| 配置 | `myid` 和 server 列表正确 |
| 幂等性 | 所有测试节点清理完成 |

脚本最终按六类结果计算成功率：容器、服务可访问性、集群一致性、基本功能、数据同步和节点配置。整体通过必须同时满足成功率至少 `80%`，并且 `GLOBAL_FAILURES=0`；否则返回退出码 `1`。清理后的幂等性检查会记录残留节点警告，但当前不计入这六类成功率。

## 关键命令、预期结果与通过条件

| 脚本执行的命令或操作 | 预期结果 | 该项通过条件 |
|---|---|---|
| 检查 `zoo1/2/3` 容器 | 三个容器均出现在 `docker ps` | `all_running=true` |
| 对 2181/2182/2183 执行端口和 `ruok` 检查 | 端口可连接，`ruok` 返回 `imok` | 三个节点全部可访问 |
| 三个节点分别执行 `stat` | 共解析到 3 个节点、1 个 Leader、至少 1 个 Follower | 集群一致性类别通过 |
| `create /test-node value` | 返回 `Created /test-node` | 普通节点创建通过 |
| `get/set/delete /test-node` | 分别匹配值、更新结果和删除结果 | 三项 CRUD 各自通过 |
| `create -e`、`create -s` | 返回相应节点路径 | 临时节点和顺序节点命令通过 |
| 在 Leader 创建 `/sync-test` 后从 zoo1/2/3 读取 | 三个节点都返回相同测试值 | `sync_success=true` |
| 检查每个容器的 `myid` 和 server 列表 | 三个节点配置均符合脚本预期 | `all_configs_correct=true` |
| `ruok`、`stat`、`mntr` | 核心命令返回脚本指定文本 | 核心四字命令无明确失败 |
| 清理后查询测试节点 | 返回 `Node does not exist` | 幂等性检查无残留警告 |

脚本不会主动停止 ZooKeeper 容器，因此不包含真实节点故障恢复测试。

## 日志与失败定位

日志固定保存到 `test/test-log/test-zookeeper-时间戳.log`，不再在运行中改写到项目根目录。所有 `nc`、四字命令、zkCli 和容器输出都会进入日志；明确失败时追加三个节点最近日志并返回非零状态。

常见问题：四字命令白名单、`myid` 与 server 列表不一致、端口映射错误、选举端口不通或旧数据卷中的集群配置冲突。
